## 起動する

Windows で開発・確認している (他プラットフォームは未検証)。

```powershell
cargo build --workspace

# .clap は DLL のリネーム。
# 先に消してからコピーすること。cargo が DLL を作り直すと .clap 側が古いまま
# 取り残されるうえ、-Force だけでは上書きされないことがある (直したはずの
# プラグインで古い挙動が出たらこれを疑う)
#
# 置き場は target\ の直下。target\debug\ に置くと cargo clean -p で消えるので、
# test_plugin.vst3 と同じ場所に揃えてある
Remove-Item target\test_plugin.clap -ErrorAction SilentlyContinue
Copy-Item target\debug\test_plugin.dll target\test_plugin.clap

# GUI ホストを起動 (--bin の指定が必要。smoke 系のバイナリも同居しているため)
cargo run -p egui-clap-host --bin egui-clap-host -- target\test_plugin.clap

# 実プラグインで起動する
cargo run -p egui-clap-host --bin egui-clap-host -- "<音源へのパス>.clap"
```

引数なしでも起動でき、あとから画面上で音源を読み込める。

### 検証用バイナリ

`host/src/bin/` に**オーディオデバイス不要**の検証バイナリが並ぶ。

```powershell
cargo run -p egui-clap-host --bin smoke -- target\test_plugin.clap       # ロード→発音→波形確認
cargo run -p egui-clap-host --bin seq_smoke -- target\test_plugin.clap   # 再生エンジンの検証
cargo run -p egui-clap-host --bin wav_smoke -- target\test_plugin.clap   # WAV 書き出しの検証
cargo run -p egui-clap-host --bin choke_smoke -- target\test_plugin.clap # 停止・シークで音が止まるかの検証
cargo run -p egui-clap-host --bin state_smoke -- target\test_plugin.clap # 音作りの保存・復元の検証
cargo run -p egui-clap-host --bin gain_smoke -- target\test_plugin.clap  # 検証用エフェクトの挙動確認
cargo run -p egui-clap-host --bin chain_smoke -- target\test_plugin.clap # チェーンの検証 (段の順序・出力を持たない段)
cargo run -p egui-clap-host --bin route_smoke -- target\test_plugin.clap # トラック間のルーティングと MIDI 割り当ての検証
cargo run -p egui-clap-host --bin loop_smoke -- target\test_plugin.clap  # ループの折り返しの検証
cargo run -p egui-clap-host --bin meter_smoke -- target\test_plugin.clap # ラウドネス・スペクトルの検証

# フォルダ走査の検証 (渡したフォルダの中身を実際に開く)。
# 引数なしで実行すると、この環境の標準の置き場を一覧するだけで終わる。
# 3回まわして、遅かったファイル・差分走査・別プロセスとの一致を出す。
# 別プロセス走査には egui-clap-host の実行ファイルが隣に要る
cargo run -p egui-clap-host --bin scan_smoke -- target

# Opus 書き出しの検証 (音源不要。呼び出し側のスタックを細くしても通るかを見る)
cargo run -p egui-clap-host --bin opus_smoke
cargo run -p egui-clap-host --bin opus_smoke -- 262144   # 256KiB のスレッドから呼ぶ

# VST3 バックエンドの検証 (実物の .vst3 が要る。test-plugin は CLAP 専用のため)
cargo run -p egui-clap-host --bin vst3_smoke -- "<音源へのパス>.vst3"

# CLAP と VST3 を別トラックに載せた同時再生の検証
cargo run -p egui-clap-host --bin mixed_smoke -- target\test_plugin.clap "<音源へのパス>.vst3"

# VST3 のエディタを開けるかだけの検証 (音は鳴らさない。GUI ウィンドウが一瞬出る)
cargo run -p egui-clap-host --bin editor_smoke -- "<音源へのパス>.vst3"

# エディタを開いたまま保持して手で触る (--busy でオーディオスレッド相当を並走、
# --egui で本体と同じ eframe の窓を並べる。再描画まわりを触ったらこれで確認する)
cargo run -p egui-clap-host --bin editor_smoke -- "<音源へのパス>.vst3" --hold
cargo run -p egui-clap-host --bin editor_smoke -- "<音源へのパス>.vst3" --egui --repaint-ms 33

# ユニットテスト
cargo test -p egui-clap-host --lib
```

### test_plugin.clap には3つ入っている

| 索引 | ID | 中身 |
|---|---|---|
| 0 | `com.example.test-sine` | 16ボイスのサイン波音源 |
| 1 | `com.example.test-gain` | `out = in * gain + offset` のエフェクト |
| 2 | `com.example.test-monitor` | **出力を持たない**モニタ (アナライザ相当) |

エフェクトのほうは**音声ルーティングの検証治具**で、音として使うものではない
(経緯は [archive/routing_plan.md](archive/routing_plan.md))。**索引0 が音源のまま**なので、
最初の1つを取る検証バイナリは今まで通り音源を掴む。

モニタは**出力ポートを1つも持たない**プラグインで、[出力を持たない段](#出力を持たない段-モニタリング系)
の検証に使う。見た音のピークを `Observed Peak` パラメータで返すので、
「素通しにしたうえで音が届いているか」を数値で確かめられる
(段ごと飛ばす実装でも出音は同じになるため、出音だけでは区別がつかない)。

**モニタにはエディタがある。** 「エディタを開く」で、その段に入ってきた音の
スペクトルとラウドネス (M / S / I) が出る。上部のマスターメーターと並べれば、
**素通しの段を挟んでも音が変わっていないことを目で確かめられる**。

画面から読み込むと**候補が3つ出る**ので、どれかを選ぶことになる。

#### test-plugin はホストと何も共有しない

**依存も測定コードもホストから切り離してある。** `.clap` 単体で他の DAW に
読ませても同じように動く。モニタのメーターは `test-plugin/src/monitor_meter.rs`
に別実装で持っており、ホストの [`meter`](#マスターメーター-画面上部) とは
コードを共有していない。

共有すると、**二つの表示を見比べても「同じコードが同じ値を出している」ことしか
言えなくなる**。別々に書いた実装が同じ値を出すことに意味がある。
K特性の係数が BS.1770-4 の 48kHz の表と一致することは、
プラグイン側のユニットテストで縛ってある。

**サイン波音源にはエンベロープが無い。** ノートオンで位相を 0 に戻し、ノートオフで
振幅そのままの状態から即座に止まるので、**ノートの切れ目で「プツッ」と鳴る**
(音の終わりや再生の終了で顕著)。検証に使う波形を素直に保つためで、不具合ではない。
実際のプラグインはどれもリリースを持っているので起きない。
段差を測っている `loop_smoke` にも、この分がそのまま出る。

### テスト治具: test-plugin の VST3 版

`test-plugin` は CLAP 専用なので、そのままでは「同じ音源を両方の形式で鳴らして
突き合わせる」ができない。[clap-wrapper](https://github.com/free-audio/clap-wrapper)
で VST3 版を作れる。**CMake と C++ ツールチェーン (Windows では VS Build Tools) が要る。**
成果物はテスト用で、配布物には含まれない。

```powershell
# リポジトリの外に置く (本体には何も入れない)
git clone --depth 1 https://github.com/free-audio/clap-wrapper.git
cmake -S clap-wrapper -B build `
      -DCLAP_WRAPPER_DOWNLOAD_DEPENDENCIES=ON `
      -DCLAP_WRAPPER_OUTPUT_NAME=test_plugin `
      -DCLAP_WRAPPER_WINDOWS_SINGLE_FILE=FALSE
cmake --build build --config Release --target test_plugin_as_vst3

# できたバンドルを本体の target/ へ (target は .gitignore 対象)
Copy-Item build\Release\test_plugin.vst3 <repo>\target\test_plugin.vst3 -Recurse
```

VST3 版は**同名の .clap を CLAP の探索パスから探して読み込む**作り。
システムにインストールせずに済ませるため、`CLAP_PATH` で場所を教える。

```powershell
$env:CLAP_PATH = "$PWD\target"
cargo run -p egui-clap-host --bin mixed_smoke -- target\test_plugin.clap target\test_plugin.vst3 --same-plugin
```

`--same-plugin` を付けると、片方だけ鳴る区間の音量が両形式で一致することまで
確かめる (ベロシティやゲインの扱いが形式で食い違うと落ちる)。

**`.clap` の中身がそのまま VST3 のクラスになる。** 音源とエフェクトの2つが
入っているので、VST3 版にも2つ入る。エフェクトの入力経路を両形式で
突き合わせられるので、チェーンの検証はこちらも通しておくとよい。

```powershell
cargo run -p egui-clap-host --bin chain_smoke -- target\test_plugin.clap target\test_plugin.vst3
```

依存は VST3 SDK 3.8.0 の `base` / `public.sdk` / `pluginterfaces` / `cmake` だけを
取得する (vstgui は含まれない)。ソースとビルド成果物を合わせて **約 80 MB** だった。
CMake 4.4.2 / VS Build Tools 2022 で通っている (2026-08-17 時点)。

## 使い方

1. **「オーディオトラック」の窓**で音源を載せ、鳴らす打ち込みトラックを割り当てる

   **音源は打ち込みトラックではなくオーディオトラックに載る。** 一覧で番号を
   押すと詳細が開くので、そこで「＋ 音源 / エフェクトを足す」→ **MIDI** の欄で
   打ち込みトラックを選ぶ。**起動直後はどこも未割り当て**なので、割り当てるまで
   打ち込みトラック欄の「♪」は赤いままになる。

   **MIDI の欄は番号のボタンが並び、複数押せる。** 押されているものが、その音源へ
   流れる打ち込み。ドラムをキック・スネア・ハイハットと別の打ち込みに書いて、
   音源1つで受ける、という使い方ができる (逆に、同じ打ち込みを複数の音源に
   割り当てて重ねることもできる)。1本の音源が受けられるのは**8本まで**。

   音源を選ぶときは先に形式を決める (それに合ったダイアログが開く)。

   | 選ぶもの | 開くダイアログ | 対象 |
   |---|---|---|
   | CLAP (.clap ファイル) | ファイル選択 | `Foo.clap` |
   | VST3 (.vst3 フォルダ) | フォルダ選択 | `Foo.vst3\Contents\x86_64-win\Foo.vst3` (現行の標準) |
   | VST3 (.vst3 単体ファイル) | ファイル選択 | フォルダになっていない `Foo.vst3` (古い形式) |

   .vst3 が2択なのは、**同じ拡張子で入れ物が2通りある**ため。Windows の共通ダイアログは
   フォルダとファイルを1つの選択で混ぜられないので、開く前にどちらかを決める必要がある。
   単体ファイル側はバンドルの中へも入っていけるので、`Contents\x86_64-win\` の DLL を
   直接指しても構わない (フォルダを指したのと同じ結果になる)。
2. **「+」** でトラックや段を増やし、グリッドをダブルクリックしてノートを置く
3. **「+CC」** で CC を書く段を最下段に追加する (ペダルなど。下記)
4. **Space** で再生ヘッドの位置から再生 (Shift+Space で先頭から。停止すると開始位置へ戻る)

操作の一覧は画面左下の **「? 操作ガイド」** に載せている。

プラグインが未ロードでもシーケンスの編集はできる (音が出ないだけ)。
先に打ち込んでから音源を読み込んでも、そのまま再生できる。

## 主な機能

### トラックと段

- **トラック > 段** の入れ子構造。トラックごとに音源 (CLAP / VST3) を1つ持てる
- ミュート (M) / ソロ (S)。ソロが1つでもあれば、ソロのトラックだけが鳴る
- スウィング (W) / 不均等な拍 (V)。トラックごとに掛ける／掛けないを切り替える
  (**併用できる**)
- 段はトラック内の表示行で、音高とは独立 (どの段に置いても音は変わらない)
- **段は「音符段が上、CC 段が下」で並ぶ。** 増減は種別ごとに別のボタン
  (`段 [+] [−]` と `CC [+] [−]`) で、通常段を足しても CC 段の下には潜らない
- ノートのある段・トラックは削除できない (事故防止)

トラック欄は高さが足りれば2段で表示し、狭いときは1行に畳む
(隠れると段を増やせなくなるため)。

**トラック欄の右端 (いちばん左の小節との境) に段ごとの緑の帯**があり、押すと
その段のノートを全選択する。押した帯は**赤**になって相手待ちになり、続けて別の段の
帯を押すと**2つの段を入れ替える** (もう一度同じ帯を押すと取り消し)。トラックを
またいでも入れ替えられる。音符段と CC 段は入れ替えられず、選べない帯は暗く描く。
CC 段どうしのときは番号も一緒に動くので、ブロックは書いた当時の CC のまま。

**赤は「その段を選んでいる」印**なので、選択が変わると相手待ちも解ける
(何もない場所を押して選択を解いたのに、帯だけ赤く残って入れ替わる、という
事故を防ぐため)。

### ノート編集

- 範囲選択 (空白ドラッグ)、一括移動、端ドラッグでの一括伸縮。
  段がノートで埋まっていても始められるよう、**いちばん下の段より下の余白からも**
  範囲選択できる (左ドラッグはスクロールに使わない。スクロールは中ドラッグかホイール)
- ← で選択の頭を揃える / → で尾を揃える (音価を伸ばす)
- ↑↓ で半音、Shift+↑↓ でオクターブの移調 (音階の上限で自動的に繰り上がる)
- Alt+ホイールでベロシティ変更、Ctrl+ホイールで段の縦幅、Ctrl+中ドラッグで横幅を拡大 / 縮小
- Ctrl+C / X / V (貼り付けは再生ヘッド位置)、Ctrl+B も貼り付け、Ctrl+Z / Ctrl+Y
- 連符 (3〜7)、左端からの音価変更 (アルペジオ・グリッサンド向け)

**コピーした中身は OS のクリップボードに書かない。** ノートをコピーするたびに
他所でコピーした内容を壊してしまうため。控えはアプリ内に持ち、他アプリの
テキストが入っていても Ctrl+V でノートが貼れる。

ただし egui-winit は Ctrl+V をキーとして通さず、**クリップボードにテキストが
あるときだけ**貼り付けイベントを作る。そのため**空のときに限り短い印を書いて**
発火させている (中身があるときは触らない)。クリップボードの状態に依存しない
道として **Ctrl+B** も貼り付けに割り当ててある。

### CC 段 (ペダルなど)

トラック欄の **「+CC」** で、CC を書く段を最下段に追加できる。番号は「CC」ボタンで
開く一覧から変える (ペダル 64 / モジュレーション 1 / エクスプレッション 11 など)。
CC 段は**背景もブロックも緑**にしてあり、音符段と取り違えないようにしている。

- **値はベロシティをそのまま使う** (0〜127)。ラベルは `CC64=100` の形で出る
- **書いた区間だけ効く。** ブロックの頭で値を、尻で 0 を送る

MIDI に「CC 無し」という状態は無く、コントローラは次の値が来るまで前の値を
保持し続ける。そこで**解除値 0 を送ることで無効状態を表している**。ペダル (CC64) は
64 以上で踏む・未満で離すなので、これがそのまま「書いた区間だけ踏んでいる」になる。

- **隣り合うブロックの境目では 0 を挟まない** (挟むと一瞬離して踏み直しになる)
- **停止・シークでも 0 に戻す。** バックエンドが自分の効かせた CC を覚えていて、
  音符の choke と同じ流れで解除する (踏みっぱなしで残らない)
- **CC ブロックは段から動かせない** (別の段へ移すと黙って別の CC になるため)。
  音符も CC 段へは入らない。横方向の移動は自由

**0 が中立でない CC (7 音量 / 8 バランス / 10 パン) には警告を出す。** 「書いていない
区間 = 0」が無音や左端になってしまうため、区間を切らずに書く必要がある。

### スウィング

ジャズのスウィングを**再生と書き出しにだけ**乗せる。記譜は8分の等分のままなので、
編集・コピー・頭揃えは今までどおり格子の上で行える。

典拠は Nelias らの *Downbeat delays are a key component of swing in jazz*
(Communications Physics, 2022)。伴奏が正確な拍を刻み、**ソリストが表拍だけを遅らせる**
という枠組みで、**裏拍の比**と**表拍の遅れ**の2つを持つ。どちらもテンポで変わる。

| 要素 | 式 | 例 (120BPM) |
|---|---|---|
| 裏拍の比 | `-0.00003(T-200)² + C`、下限 1.0 | 1.31 (裏拍が 0.567 拍の位置へ) |
| 表拍の遅れ | `(-0.3T + 130)` tick、上限 60ms | 49ms |

`C` はツールバーの **「スウィング」** スライダー (1.00〜2.00)。`1.00` で全テンポが
直線になり、`2.00` でピーク時 (200BPM) にちょうど三連スウィングになる。
掛けるトラックは左のトラック欄の **「W」** で選ぶ。**N/4 拍子のときだけ**有効
(N/8・N/16 はそもそも均等に近いため)。

判定は位置だけを見るので、**三連符は自動的に対象外**になる (拍頭と裏拍以外は動かない)。
連符モードとの排他制御は要らない。

### 不均等な拍 (ウィンナ・ワルツ風)

**小節の中で拍の長さ自体を変える。** 3拍子なら「短・長・短」——**2拍目が前に出る**形。
5拍子なら「短・中・長・中・短」と、中央の拍を頂点にした左右対称になる。
こちらも**再生と書き出しにだけ**乗り、記譜は等分のまま。

ツールバーの **「拍の偏り」** スライダー (0.50〜2.00) が
**端の拍 ÷ 中央の拍**。掛けるトラックは左のトラック欄の **「V」** で選ぶ。

| 値 | 形 | 3/4 の拍の長さ |
|---|---|---|
| 0.50 | 山 (強) | 0.75 / 1.50 / 0.75 |
| **0.85** (既定) | 山 | 0.944 / 1.111 / 0.944 |
| 1.00 | 均等 (無効) | 1 / 1 / 1 |
| 2.00 | 谷 (強) | 1.2 / 0.6 / 1.2 |

**1.00 未満が山** (ウィンナ・ワルツ風)、**1.00 超が谷** (中央が短い)。
`1.00` で無効と等価になる。

**有効なのは奇数の N/4 拍子** (3/4・5/4・7/4…) のときだけ。中央の拍が1つに
定まる形なので偶数は対象外。

スウィングとは**併用できる**。適用順は **スウィング → 拍の伸縮**。スウィングの
判定が拍頭と裏拍の位置を見るため、先に拍を伸縮すると当たらなくなるので、
この順序は入れ替えられない。

**小節の長さは変わらない** (拍長の総和が拍数に一致する)。テンポもループ点も
動かず、スウィングと違って音価が負になったり順序が入れ替わったりもしない
(時間軸ごと写すので写像が単調)。

強さの既定値はスウィングと違って**典拠が無く、耳で決めた出発点**
([archive/waltz-plan.md](archive/waltz-plan.md))。

書き出した MIDI にも跳ねが乗る。読み戻すと跳ねが二重に掛かるので、
編集を保存する用途には使わないこと。

### 表示

ノートの見た目に3つの情報を載せている。

- **色相 = 音高**: オクターブごとにアクセント色を巡回し、半音が上がるほど次のオクターブの色へ混ざる
  (**CC 段のブロックは緑固定**。音高で色を変えても意味がないため)
- **塗りの高さ = ベロシティ**: 明度を下げるとダーク背景で弱いノートが見えなくなるため、
  色は変えずに下から塗り、残りは同色のゴーストとして残す
- **ラベル** = `(半音, オクターブ)` / CC 段では `CC64=100` (段を縮めて入らなくなると省かれる)

**段の縦幅 (縦ズーム)** はツールバーの「段幅」か、グリッド上の **Ctrl+ホイール** で
12〜96px の範囲で変えられる。段が少ないときに広げるとノートを掴みやすくなる。
左のトラック欄も同じ高さで並ぶ (行の位置が揃うため)。

**横幅 (横ズーム)** は **Ctrl+中ドラッグ** (左で拡大・右で縮小)。ツールバーの
「横幅」で既定へ戻せる。どちらのズームも**掴んだ位置・カーソルの下が画面上で
動かない**ようスクロールを合わせる。横ズームでは倍率と横位置を同じフレームで
決めており、差分で追従させると1フレームずれて画面が揺れる。

再生中は再生ヘッドが画面から出ないよう追従し、**停止すると開始位置へ画面ごと戻る**
(画面外にあるときだけ動かすので、少し再生して止めただけでは跳ねない)。

テーマは [vim-hybrid](https://github.com/w0ng/vim-hybrid) 風のダークテーマ (`theme.rs`)。

**1文字の切り替え (M / S / W / V / B) は、入っているときだけ色を付ける。**
打ち込みトラック欄とオーディオトラックの窓で同じ流儀に揃えてある。

| | 意味 | 色 |
|---|---|---|
| M | ミュート | 赤 |
| S | ソロ | 黄 |
| W / V | スウィング / 不均等な拍 | 水色 |
| B | バイパス | 水色 |

**赤は「鳴らない」に取ってある。** バイパスは音が通る (素通しになるだけ) なので
赤にしていない。W / V と同じ「この切り替えが入っている」の水色に揃えた。

### マスターメーター (画面上部)

上部の帯に**マスター (オーディオトラック0) の出力**を出す。閉じられない
(常に見えているほうがよいという判断)。

| | 中身 |
|---|---|
| スペクトル | 30Hz〜18kHz を対数で56帯に分けたもの。左が低域、縦線が 1kHz |
| **M** | Momentary — 直近 400ms のラウドネス |
| **S** | Short-term — 直近3秒のラウドネス |
| **I** | Integrated — **頭からの積算** (最後に読む値なので太字) |
| 横棒 | 塗りが Short-term、**白い縦線が基準の −14 LUFS**、黄色い縦棒が Integrated |

読み値は基準との差で色が変わる。**±1 LU 以内なら緑**、大きければ赤 (配信側で
下げられる)、小さければ水色。横棒の塗りが Short-term なのは、Momentary は
揺れが速くて目盛りとして読めないため。

**Integrated は再生を始めたときとループの折り返しで測り直す。** ループで
ずっと回しながら「この1周ぶんの積算」を見るための決め。M と S は**測り直さない**
(直近を見るものなので、折り返しのたびに −∞ へ戻ると読めなくなる)。
積算は BS.1770 の2段ゲート付き — 無音 (−70 LUFS 未満) と、平均から 10 LU 下を
落とすので、曲間の静かな部分に引きずられない。

**再生中のシークでは測り直さない。** 飛んだ先も同じ通しとして積算が続く。


測定は ITU-R BS.1770-4 に従う。**K特性の係数はそのときのサンプリングレートから
引き直している** — 規格が表で載せているのは 48kHz のものだけで、44.1kHz の
デバイスにそのまま当てると読みがずれる。EBU Tech 3341 の試験信号1
(1kHz 正弦波 −23.0 dBFS) が −23.0 LUFS を示すことを、テストと `meter_smoke` の
両方で毎回確かめている。

計測そのものは**メインスレッドで行う**。オーディオスレッドはマスターの
サンプルをリングバッファへ写すだけで、詰まっていればそのブロックを捨てる
(メーターが欠けても音には影響しない)。

### 音階モード

ホストが変えるのは MIDI ノート番号だけで、実際の音高はプラグイン側の音律設定
(Scala の `.scl` ファイルなど) が決める。ノート番号は
`60 + (オクターブ - 4) × ステップ数 + 半音` で算出し、`(0,4)` が常に 60 (中央ハ) になる。

| モード | ステップ数 | 半音の範囲 | 例 |
|---|---|---|---|
| 12平均律 | 12 | 0..=11 | `(0,4)`→60 (C4) / `(9,4)`→69 (A4) |
| B-P 13音 | 13 | 0..=12 | `(0,4)`→60 / `(3,4)`→63 (平均律 E♭4 と同番号) / `(0,5)`→73 |

ボーレン・ピアースはトライターブ (3:1) を13等分する音階。モードを12平均律に戻すと、
半音12のノートは11に丸められる。

### プロジェクトの保存 (.ron)

画面下の **「ファイル」** メニュー、または **Ctrl+S** で `.ron` に保存する。
形式は [RON](https://github.com/ron-rs/ron) で、テキストなので diff も取れる。

```ron
(
    version: 4,
    tempo: 96,
    beats: 3,
    beat_type: 4,
    scale: BohlenPierce13,
    swing_peak_ratio: 1.75,
    tracks: [
        // lane_ccs は CC 段があるときだけ出る (段1 が CC64 = ペダル)
        (name: "リズム", lanes: 2, muted: true, soloed: false, swing: false,
         lane_ccs: [None, Some(64)]),
        (name: "ソロ", lanes: 1, muted: false, soloed: false, swing: true),
    ],
    notes: [
        (start: 0.0, duration: 0.5, semitone: 3, octave: 4, velocity: 100, track: 0, lane: 1),
    ],
    // 巨大になりうるので末尾 (下記)
    audio_tracks: [ ... ],
)
```

- **記譜位置をそのまま残す** (スウィングも拍の偏りも焼き込まない)。MIDI と違って
  往復しても崩れない
- スウィングと拍の偏りの ON/OFF や強さ、ミュート/ソロ、音階モード、CC 段の
  割り当ても保存される
- **音源とその音作りも保存される**。開き直すと同じ音源が同じ状態で載る (下記)

### プラグイン一覧 (画面上部の「プラグイン」)

フォルダを登録して中の `.clap` / `.vst3` を走査し、**一覧から音源を選ぶ**。
初回起動時は規格が決めている置き場のうち実在するものが入る。

| タブ | 中身 |
|---|---|
| 音源 / エフェクト | プラグインが**宣言している**種別で分ける |
| 未分類 | 宣言が読めなかったもの (下記) |
| お気に入り | ★ を付けたもの。種別を問わない |

記録は**実行ファイルの隣の `config\plugins.ron`**。`cargo run` で動かすと
`target\debug\config\` に落ちるので、**`cargo clean` すると消える**
(走査し直しには時間がかかるので、消したくないときは退避すること)。

オーディオトラックの「＋」を押すとこの窓が「載せる先を待っている」状態になり、
一覧の行を押すとそこへ載る。**一覧に無いものは「ファイルから直接…」**で
ファイルを選んで読み込める。

**載せるとこの窓は閉じる。** 開いたままだと、載ったのかどうかが画面から
読み取れない。段を続けて足すときは、そのつど「＋」から入り直す。

**種別はクラスごとに分かる。**

| 形式 | 出どころ | 走査の重さ |
|---|---|---|
| CLAP | `PluginDescriptor::features()` | モジュールを読むだけ |
| VST3 (`moduleinfo.json` あり) | JSON の `sub_categories` | **JSON を1つ読むだけ** |
| VST3 (無し) | ファクトリの `sub_categories` | モジュールを読むだけ |

副カテゴリを宣言していないものだけが「未分類」に残る。**間違った分類より、
分からないと言うほうがよい**という判断。

**どの道もプラグインを作らない。** `vst3-host` の `get_detailed_plugin_info`
は使わない — あれは**こちらが要りもしないバス構成を調べるために
`createInstance` と `initialize` を呼ぶ**。音源はそこでウェーブテーブルや
プリセットを読むので、1本で数秒かかる。

代わりに `list_plugin_classes` を使う。**フォークに足した関数**で、モジュールを
読んでファクトリに聞き、そこで止まる。これが入るまでは JSON の無いファイルに
ファイル全体のカテゴリを当てるしかなく、**音のクラスが2つあると両方まとめて
「未分類」**になっていた (当てると間違える。検証用の VST3 でエフェクトが
音源として出た)。

#### 差分走査

**「走査」は変わっていないファイルを開き直さない。**

`Entry` は走査した時点のファイルの**印** (更新時刻とバイト数) を持っていて、
一致すれば前の記録をそのまま戻す。2回目以降はほとんどがここで落ちるので、
90本あっても入れ替えた数本を開くだけで終わる。終わったときの知らせに
「何件を開き、何件を使い回したか」が出る。

**`.vst3` はバンドルディレクトリのことがある。** ディレクトリの更新時刻は
中を書き換えても動かないので、印は**中の実体**から取る
(`discovery::stamp`)。印が取れなければ開いて確かめる側へ倒す。

印を見ずに全部開くのが**「すべて開き直す」**。分類がおかしいときに使う。

**走査器の版が変われば印は自動で捨てる。** ファイルが同じでも、こちらが
読み取る中身が変わっていれば記録は古い。`library::SCANNER_VERSION` を上げると、
次の走査で印を信用せず全部開き直す (Ardour の
`ARDOUR_VST3_CACHE_FILE_VERSION` と同じ役目)。読み取りを直したら**ここを
上げること**。上げ忘れたときの逃げ道が「すべて開き直す」。

#### 別プロセスで開く

**既定でプラグインは別のプロセスで開く** (`subscan`)。走査はプラグインの DLL を
実行することと同じで、行儀の悪いものはホストごと落とす。ライセンス確認に
失敗して `abort()` を呼ぶもの、純粋仮想関数を叩くもの。**`catch_unwind` では
助からない** (`abort()` は巻き戻さずにプロセスを終わらせる)。

落ちてよい相手を用意するしかない。Ardour が `ardour-vst3-scanner` を、
Zrythm が `carla-discovery` を別に持っているのと同じ形。

- **子はこの実行ファイル自身。** `--scan-one <プラグイン> <書き出し先>` で
  起動すると、窓を出す前に1ファイル開いて結果を書き、終わる
- **結果はファイルで渡す。標準出力は使わない。** プラグインは平気で標準出力へ
  書くので、同じ流れに結果を混ぜると壊れる
- **子が落ちたら、そのファイルは `blocked` へ入る。** 次の走査では開きに行かない
- 1ファイルに 30 秒。超えたら殺す (`subscan::TIMEOUT`)
- **落ちたときだけ飛ばす。** 「開けない」で終わったものは飛ばさない
  (`CLAP_PATH` を足せば読める、のように直せる理由があるため)

**代償はプロセスを起てる時間。** 手元の実測で 1ファイルあたり 300〜500ms
(開発機・release ビルド)。これは実行ファイルの大きさではなく **Windows の
プロセス生成そのもの**で、即座に終わる 887KB のバイナリでも 348ms かかった
(ウイルス対策の実時間監視の影響が大きいと思われる)。90本なら 30〜45 秒。

**差分走査があるので1回だけの出費**だが、フォルダ行の「別プロセス」を切れば
同じプロセスで開ける。切ると速いが、落ちたときは道連れになる。

#### 走査中の反応

走査は**1フレームに1ファイルずつ**進める。CLAP も VST3 もモジュールの
読み込みがメインスレッドの規約に縛られていて裏へ回せないため。VST3 は1本に
数秒かかることがあるので、今開いているファイル名を出している。

**同じプロセスで開く設定でも、落ちれば分かる。** 開く直前のパスを
`config\scanning.txt` に書いており、次の起動でそれが残っていればそのファイルを
走査から外して知らせる。別プロセスなら親が生きているので、その場で分かる。

#### 検証用の `test_plugin.vst3` は走査で読めない

`target` を走査フォルダに登録すると、`test_plugin.vst3` だけ
`GetPluginFactory returned null` で落ちる。**不具合ではない。**

これは clap-wrapper で作った VST3 で、「テスト治具: test-plugin の VST3 版」に
書いたとおり**同名の `.clap` を CLAP の探索パスから探す**。GUI ホストを
`cargo run` で起動すると `CLAP_PATH` が無いので見つけられない。

走査の結果には**この事情を添えて出す**ようにしてある (隣に同名の `.clap` が
あるかどうかで見分けている)。読ませたいときは、起動前に環境変数を入れる。

```powershell
$env:CLAP_PATH = "$PWD\target"
cargo run -p egui-clap-host --bin egui-clap-host
```

なお `target` は普段から走査フォルダに入れておく場所ではない
(ビルドの出力先で、`cargo clean` で中身ごと消える)。

### 音源の保存 (オーディオトラック)

音源は**オーディオトラック**に載る。打ち込み側の「トラック」とは別の系統で、
**常に16本**あり、**0番がマスター**。ファイル末尾に置いてあるのは、
テンポ・ノートといった読みたい部分を先頭に残すため。

**段の「B」(バイパス) は、処理を止めずに出た音だけを捨てる。** 飛ばすと
イベントが届かず、ノートオフや消音を取りこぼす (鳴っている最中にバイパス →
停止 → 戻す、で音が出てしまった)。引き換えにバイパス中も CPU を使うので、
**A/B 比較のためのもので、負荷を下げる口ではない**。
ディレイやリバーブの溜まりも保たれるため、戻したときに続きから鳴る。

```ron
    audio_tracks: [
        // 0 はマスター。送り先を持たず、ここの出力が最終出力になる
        (name: "", midi_track: None, sends: [], nodes: []),
        (name: "", midi_tracks: [0], sends: [(to: 0)], nodes: [
            (kind: Clap, path: "C:\\...\\音源.clap",
             id: "com.example.synth", state: "AAECAwQFBgcICQoL..."),
        ]),
        // 以下、空のトラックが 16 本になるまで並ぶ
    ],
```

- **`nodes` は上から順に通す列。** 音源とエフェクトを区別しない
  (違いは入力ポートを持つかどうかだけ)。**画面から積めるのはまだ1段**で、
  2段以上あるファイルは先頭だけ載せて残りを通知に出す
- **`midi_tracks` がどの打ち込みトラックから MIDI を取るかを決める。**
  対応は多対多で、同じ打ち込みを複数のオーディオトラックが見てもよく (重ねられる)、
  1本のオーディオトラックが複数の打ち込みを受けてもよい (ドラムの叩き分けなど)。
  受けられるのは**8本まで**で、超えたファイルは読み込みで断る
- **`sends` は送り先。片側だけ書く。** 両側に書くと「A は→B と言い、B は何も
  言っていない」という矛盾したファイルが作れてしまう。
  1本を複数へ送れば枝分かれ (センド) になり、**送り先どうしで足し合わさる**。
  マスターへ辿り着けないトラックは鳴らない (一覧で赤枠になる)
- `gain` / `pan` / `muted` / `soloed` も保存される。**ソロは経路を辿って残す**
  ので、バスへ送っているトラックをソロにしてもバスは鳴り続ける
- **`gain` は線形。** 画面では dB (0 dB が等倍) で出しているが、ファイルと
  エンジンは線形で持ち、境目で変換する
- **古いファイルは自動で移る。** バージョン2 以前は、打ち込みトラック `i` の音源が
  オーディオトラック `i + 1` の1段目になる (0 がマスターなので1つずれる)。
  **16本に収まらないぶんは名指しで知らせる** (黙って捨てない)。
  バージョン3 の `midi_track` (1本まで) は `midi_tracks` へそのまま移る
- **パスだけでなくプラグイン ID も持つ。** 1つの `.clap` に複数のプラグインが
  入りうるので、パスだけでは特定できない (VST3 はクラス UID)
- **状態は音源自身に書き出させる** (CLAP は `clap.state`、VST3 は `IComponent::getState`)。
  パラメータを列挙するのでは足りない (プリセットやウェーブテーブルなどパラメータに
  現れない状態があるため)。中身は不透明なバイト列で、ホストは解釈せず base64 で載せるだけ
- **読み込みに失敗したトラックは音源なしになる。** ノートは残り、どのトラックが
  失敗したかを通知に並べる。音源は載ったが状態だけ戻せなかった場合は、
  音源を残して初期値のままにする

**壊れたファイルは読み込まない。** 構文を解析したあと意味の検証を行い、問題が
1つでもあれば**エディタには一切触れずに**まとめて理由を表示する
(テンポや拍子の範囲、音価0、NaN、存在しないトラックへの参照など)。
オーディオトラックについては、送り先の範囲・自分自身への送り・重複・
マスターが送り側になっていないか・**繋ぎ方が輪になっていないか**を見る
(輪を通すと再生時に無限に辿ることになる)。打ち込みの割り当て本数もここで見る
(画面では上限まででしか選べないが、手で書いたファイルが入口になりうる)。
知らないフィールドは無視し、欠けたフィールドは既定値で埋めるので、
バージョン違いのビルドでも開ける。互換性の門は `version` 1本。

### MIDI 入出力

**読み込みは「ファイル > MIDI インポート」、書き出しは「出力 > MIDI ファイルとして
出力」。** 書き出しは音声や CCS と同じ「出力」に置いてある — 記譜をそのまま
残すものではなく、**揺らぎを焼き込んだ結果**を出すものだから。
書き終えると通知が出て、揺らぎが乗っていればそのことも添える。

- **(トラック, 段) の組ごとに1つの SMF トラック**として書き出し、トラック名に
  `Track 0 Lane 2` の形で番号を埋める。読み戻すと配置がそのまま復元される
  (段数16の制限を受けず、同じ段での重なりも保たれる)
- チャンネルにも `段 % 16` を入れてあるので、チャンネルで分けるアプリでも分離して見える
- **CC 段はコントロールチェンジとして書き出す** (頭で値・尻で 0)。再生時とまったく
  同じ並びなので、書き出した MIDI でもペダルは踏みっぱなしにならない
- **読み込みでは書き出しの規則を逆にたどる**。値が 0 でないところで始まり、
  次のイベント (0 か別の値) で終わるブロックとして戻す。自分で書き出した
  ファイルなら、音符段と CC 段の配置がそのまま復元される

読み込みでは**一度も値の変わらないコントローラを段にしない**。DAW の書き出しには
「先頭で音量を1回だけ送る」ような初期設定が入っていることが多く、そのまま段にすると
**書いてもいない帯が並ぶ**ため。チャンネルモードメッセージ (120番以降。
オールノートオフなど) も読み飛ばす。

- トラック名に段情報が無い他アプリの MIDI は、SMF トラックごとにアプリのトラックへ割り当て、
  和音は重ならない段へ機械的に散らす
- **インポート時は保存先を記録しない** (Ctrl+S で読み込み元を上書きしないため)

### 音声の書き出し

画面下の **「出力 > WAV ファイルとして出力」** で、シーケンス全体を音声ファイルにできる。

- オーディオスレッドから音源を一時的に引き上げ、実時間を待たずに最後まで回す。
  **音作りしたパラメータがそのまま乗る** (別インスタンスを立てる方式だと state 拡張が
  未対応なぶんパラメータが初期値に戻ってしまうため、この形にしている)
- 形式は 16bit PCM。サンプルレートとチャンネル数は出力デバイスの構成に従う
- 終端のあと3秒ぶん回してから末尾の無音を切り落とす (残響やリリースを拾うため)
- ピークが 0dBFS を超えたときだけ全体を定数倍で縮める (足りない音量を勝手には上げない)
- ミュート/ソロの判定は再生と同じ

書き出しが終わると通知が出る。**「フォルダを開く」でそのファイルを
エクスプローラーに出せる** (「出力」から書き出すもの全部。一部に問題があった
場合も、ファイル自体はできているので同じように開ける)。

### Opus (.opus) への書き出し

**「出力 > Opus ファイルとして出力」** から、ビットレート
(**48 / 96 (既定) / 128 / 192 kbps**) を選んで書き出す。容器は Ogg。

**Opus が鳴らせるのは 48kHz だけ**だが、ストリームはデバイスのレート
(多くは 44.1kHz) で開いている。そこで**書き出しの間だけ音源自体を 48kHz で
動かし直す**。リサンプリングではないので、**本当に 48kHz で鳴らした音**になる。

```
借りる → 48kHz へ切り替え → 描画 → 元のレートへ戻す → 返す
```

読み込み直しはしないので**音作りは保たれる** (VST3 は `IAudioProcessor` の
再設定、CLAP は deactivate → activate)。

- **戻せなかったトラックは音源ごと外して通知する。** 載っているのに鳴らない
  状態で放置するより、消えているほうが気付ける
- 出せるのは**モノラルとステレオだけ** (Opus のチャンネル対応表を真面目に
  書く範囲ではないため)
- 既定を 96kbps にしてあるのは、**低いビットレートでも音質が保たれるのが
  Opus の利点**だから
- **上限が 192kbps なのは、それ以上を必要としていないから。** 試験信号では
  510kbps まで正常なので、クレート側の制限ではない
- **符号化は専用スレッドで行っている。** `opus-rs` の `OpusEncoder::new` が
  スタックを大きく使い、**Windows のメインスレッド (既定 1MiB) から呼ぶと
  落ちる**ことがあるため

`opus-rs` と `ogg` はどちらも純 Rust で、**C のビルド環境 (CMake) は要らない**。

選べるビットレートを広げた経緯、版ごとのスタック実測、上流へ出した2件の報告は
[archive/export_rate_plan.md](archive/export_rate_plan.md) にまとめてある。

### CeVIO (.ccs) への書き出し

**「出力 > CCS ファイルとして出力」** で、**1トラック目**を CeVIO のプロジェクトにできる。
歌詞は「ラ」固定で、音程だけを渡す用途。

- CeVIO のソング Unit は単旋律しか歌えないので、**段ごとに1パート (Unit + Group)** に分ける。
  ノートの無い段はパートを作らない
- キャスト (`CastId`) は空で書き出すため、**CeVIO 側でパートごとに歌手が自動で割り当てられる**。
  特定の歌手を指定する手段はない
- CeVIO は1小節目が空白扱いなので、拍子に合わせて全体を1小節ぶん後ろへずらす
- 音源は要らない (純粋なデータ変換)。ミュート/ソロは見ない

音高の渡し方は音律で変わる。

| 音律 | 基準 | CeVIO への渡し方 |
|---|---|---|
| 12平均律 | A4 = 440Hz | ノート (PitchStep/PitchOctave) だけ。**ピッチ (LogF0) は書かない**ので、CeVIO 側の自然なピッチカーブ (ビブラート等) が乗る |
| B-P 13音 | キー63 = 311.127Hz | 12平均律の格子に乗らない (1ステップ = 146.3 セント) ため、**最寄りの12平均律音**をノートに書き、実周波数の自然対数を LogF0 で与えて補正する。ノートごとに平坦なので歌い方は機械的になる |

B-P の基準 311.127Hz は12平均律の E♭4 と同じ高さで、`(半音3, オクターブ4)` にあたる。
**この書き出しは音高を絶対値で確定させる**ので、再生側 (音源の `.scl` 設定) が
別の基準を使っているとズレる。

- **動作確認**: 3段 (3パート) の .ccs を CeVIO で開き、パートごとに別のキャストが
  割り当てられて並ぶこと、ボーレン・ピアースのピッチが意図どおり鳴ることを確認済み

## アーキテクチャ

```
[メインスレッド: egui]                    [オーディオスレッド: cpal コールバック1本]
  ノート編集・再生操作
    │ rtrb リングバッファ (GuiMsg) ──▶  トランスポート (再生位置は1つ)
    │                                      ├─ トラック0: イベント → process() → バッファ
    │                                      ├─ トラック1: イベント → process() → バッファ
    │                                      └─ …を合算して CPAL バッファへ
    ◀── 戻り用リングバッファ ─────────  外した音源 (メインスレッドで deactivate)
    ◀── crossbeam チャンネル ─────────  request_callback() などのホスト要求
```

- **出力ストリームは1本だけ**。音源はリングバッファ経由で載せ替えるのでストリームを作り直さない。
  トランスポートが1つなのでトラック間のズレが原理的に発生しない

### チャンネルはステレオまで

**グラフの中は常に 2ch。** デバイスやプラグインが何チャンネルでも、境目で合わせる。
デバイスに合わせないのは、**モノラル出力の環境で書き出しまでモノラルになる**のを
避けるため (書き出しは常にステレオ)。

| 相手 | 扱い |
|---|---|
| デバイスがステレオ | そのまま |
| デバイスがモノラル | 左右を平均して落とす |
| デバイスが 3ch 以上 | **先頭2本へ L / R を出し、残りは無音**。断らずに鳴らす |
| プラグインがモノラル | 出力は **L と R の両方へ同じ音**。入力は L/R の平均を渡す |
| プラグインが 3ch 以上 | 出力は**先頭2本を L / R として使う**。入力は L/R だけ渡し、残りは無音 |
| プラグインの出力が 0ch | **その段は素通し** (下記) |

デバイスは **ステレオ → 3ch 以上 → モノラル**の順に選ぶ。単純にチャンネル数の
多い順にすると、2ch も選べる環境で 7.1 を開いてしまう。

### 出力を持たない段 (モニタリング系)

アナライザ・チューナー・ラウドネスメーターには、**出力ポートを1つも持たない**
ものがある。ホストは器としてステレオのバッファを渡すが、プラグインはそこへ
何も書かない。その空のバッファを採ると、**そこから後ろが無音になる**。

**そういう段はバイパスと同じ扱いにする。** 音は通常どおり渡したうえで、
入ってきた音を控えておき、段を通したあとに書き戻す。プラグインからは
チェーンの途中で音が見え、後ろの段には前段までの音がそのまま流れる。
トラック欄には `2→0ch` と出る。

**「出力ポートが無い」と「出力が無音」は別。** 見ているのはポートの申告だけで、
出力ポートを持ったうえで無音を書くプラグインは、そのまま無音として扱う
(ホストからは区別できない)。VST3 では出力バスの並びを直接見る。
`vst3-host` の `output_channel_count()` は 0 をステレオに丸めるため、
そちらでは判定できない。

**目で確かめるには `Test Monitor` を刺す。** その段に入ってきた音の
スペクトルとラウドネスをエディタに出すので、上部のマスターメーターと
並べれば、素通しの段を挟んでも音が変わっていないことが見て取れる
([検証治具](#test_pluginclap-には3つ入っている))。
- オーディオスレッドではロック・アロケーションなし (リングバッファ + 事前確保バッファ)。
  イベント発行は「クロックの前進」と「トラック別の発行」に分けて固定長で持ち回る
- 音源の解放は必ずメインスレッド (外した処理器はトラック番号付きで返す)
- 再生位置はサンプル精度。停止/シーク/シーケンス差し替え時は消音イベントで鳴りっぱなしを防止

**CLAP と VST3 は enum で分岐する** (trait オブジェクトにしない)。トランスポートより
上は形式を知らず、中立の `BlockEvent` (ノートオン/オフ・消音・CC・パラメータ) だけを
やり取りする。形式ごとの差はバックエンドの中で吸収している。

| | CLAP | VST3 |
|---|---|---|
| ノート | CLAP ダイアレクト優先、MIDI しか受けない音源には生 MIDI | 生 MIDI |
| 消音 | `NoteChoke` 1つ | 鳴らしたキーを覚えて個別に note-off |
| CC | 生 MIDI (`0xB0`)。**MIDI を受けないポートには送れない** | `IMidiMapping` 経由でパラメータへ |
| 音源の持ち方 | 処理器だけを切り離してオーディオスレッドへ | `Arc<Mutex<Plugin>>` を共有し、オーディオ側は `try_lock` |

設計の経緯と実測は [archive/vst3_host_plan.md](archive/vst3_host_plan.md) に残してある。

## プラグイン独自 GUI

音源を読み込むと、画面上部に「エディタを開く」ボタンが出る。**Win32 ネイティブ
ウィンドウ (`plugin_window.rs`) は CLAP と VST3 で共通**で、HWND の渡し先が
`clap.gui` の `set_parent` か `IPlugView::attached` かだけが違う。

- **embedded モード優先**: ホストが窓を作り、プラグインに中身を描かせる。
  eframe (winit) のメッセージループが同一スレッドの全ウィンドウへ配送するので、
  追加のメッセージポンプは要らない
- **floating フォールバック**: embedded 非対応の CLAP はプラグイン自身に窓を作らせる
  (VST3 に floating に当たるものは無い)
- `clap.timer-support` 実装済み (JUCE 系プラグインの GUI 描画に必要)
- プラグインからのリサイズ要求 / ユーザーのウィンドウリサイズの双方向に対応
- **動作確認**: 手元の VST3 24個すべてでエディタが開くこと、実プラグインの UI が
  描画され操作できることを確認済み

**再描画の間隔は、エディタを開いている間だけ 33ms に落としている。** eframe は
「期限を過ぎた再描画要求」を見つけると `ControlFlow::Poll` に落とし、winit は
`RedrawRequested` のたびに配送ループを打ち切る。vsync 60Hz のフレームは
約 16.7ms なので、16ms を要求すると毎回すでに期限切れになり、ループが待機状態に
入らず**メッセージキューが常に捌き残る**。割を食うのは同じスレッドに貼り付いた
プラグインのエディタで、単発のクリックは通るのにホバーやドラッグが効かなくなる
(一部の音源で発覚。経緯は [archive/vst3_host_plan.md](archive/vst3_host_plan.md) のフェーズ7)。

## 制限事項・既知の注意点

テスト用ホストのため、以下は未対応。

- **レイテンシ補正 (PDC) なし**: レイテンシの大きいプラグインを混ぜるとトラック間で発音がずれる
- **音作りの復元は状態の入出力に対応した音源に限る**: 実装していない音源は、
  次に開いたとき載りはするが設定は初期値に戻る
- **CLAP 専用ダイアレクトの音源には CC を送れない**: CLAP に CC のイベントは無く、
  生 MIDI でしか送れないため。MIDI も受け取れるポートなら問題ない
- **CC はブロック単位のみ**: ブロック内で値を変化させる (フェードなど) 書き方はできない
- **CC の解除値は 0 固定**: 0 が中立でない CC (音量・パン) を段に割り当てると、
  書いていない区間が無音や左端になる (一覧で警告は出る)
- **MIDI エクスポートはスウィングを焼き込む**: 読み戻すと跳ねが二重に掛かるため、
  編集の保存には使えない (それは `.ron` の役目)
- **音声の書き出し中は画面が固まる**: メインスレッドで処理するため。進捗表示もない。
  Opus はレートの切り替えが両端に入るぶん、さらに長くなる
- 書き出せる形式は **16bit PCM の WAV** と **Ogg/Opus** だけ
- **書き出しは常にステレオ**。デバイスが何チャンネルでも変わらない
- **Opus のビットレートは可変 (VBR)** で、指定した値に張り付くわけではない
- **clap.tail 拡張が未対応**: 書き出しの残響は終端から3秒で打ち切られる
- **CCS 書き出しは1トラック目のみ**。ベロシティと歌詞は渡さない (歌詞は「ラ」固定)。
  歌手の指定もできない (CeVIO 側の自動割り当てに任せる)
- 音源の取り外し UI なし (差し替えのみ)
- **縦ズームを縮めると左のトラック欄のボタンが欠ける**: 段1つのトラックを 20px 未満まで
  縮めた場合。ボタンの高さは変えられないので、行を揃えることを優先している
  (トラック欄の横幅は固定)
- 出力はモノラル/ステレオのみ。ミックスは単純加算 (クリップ対策なし)
- 途中のテンポ変化に未対応 (MIDI 読み込み時は最初のテンポだけ使う)
- デバッグビルドはトラックを増やすと音切れの恐れがある (リリースビルド推奨)
- Windows のみで確認 (プラグイン GUI の埋め込みが Win32 依存)
- clack 同梱の gain-gui サンプル (egui-baseview 製) はウィンドウが白表示になる。
  baseview の WM_TIMER 駆動レンダリングとの相性問題とみられる (実プラグインでは未再現)
- 実プラグインは Windows では `C:\Program Files\Common Files\CLAP` および
  `C:\Program Files\Common Files\VST3` 配下にインストールされる
