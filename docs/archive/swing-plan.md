# スウィング機能とプロジェクト保存形式の計画

ジャズのスウィングを再生・書き出しに適用する機能と、それに伴うプロジェクト保存形式の追加。

典拠は Nelias らの *Downbeat delays are a key component of swing in jazz*
(Communications Physics, 2022)。その枠組みでは、**伴奏は正確な拍を刻み、
ソリストが表拍だけを遅らせる**。裏拍は伴奏と同期したまま、スウィング比の位置に置かれる。
数式の係数は、この論文をもとに個人的に調整した経験則。

## 確定した仕様

| 項目 | 内容 |
|---|---|
| 裏拍の比 | `-0.00003(T-200)² + C`、`C` は 1.0〜2.0 のスライダー、結果は `max(1.0)` |
| 表拍の遅れ | `(-0.3T + 130)` tick (960 TPQ 基準)、**60ms で頭打ち** |
| 適用条件 | `beat_type == 4` かつ トラックごとの ON/OFF |
| 判定 | 位置ベース（許容誤差 1e-3 拍）。連符は自動的に対象外 |
| 適用先 | **再生 / WAV / CCS / MIDI エクスポート のすべて** |
| 保存 | `.ron`（記譜位置 + 設定。スウィングは適用しない） |

### スライダー `C` の意味

数式の加算定数そのものを可変にする。`C` は**ピーク時 (200BPM) の裏拍の比**にあたる。

| C | 200BPM の比 | 裏拍位置 | 120BPM の比 | 裏拍位置 |
|---|---|---|---|---|
| **1.0** | 1.00 | 0.500 | 1.00 (clamp) | 0.500 |
| 1.25 | 1.25 | 0.556 | 1.06 | 0.514 |
| **1.5** (既定) | 1.50 | 0.600 | 1.31 | 0.567 |
| 1.75 | 1.75 | 0.636 | 1.56 | 0.609 |
| **2.0** | 2.00 | **0.667** | 1.81 | 0.644 |

`C = 1.0` で全テンポが直線（無効と等価）、`C = 2.0` でピーク時にちょうど三連スウィング。

### clamp が効き始める点

- 比の `max(1.0)`: **71BPM 未満** と **329BPM 超**
- 遅れの 60ms 頭打ち: **103BPM 以下**（120BPM は 49ms で無傷、60BPM は 117ms → 60ms）

## 変換の設計

出力がすべてスウィングするので、入口を1つにまとめる。

```rust
impl MidiEditor {
    /// 出力用にスウィングを適用したノート列。記譜 (self.notes) は変えない。
    pub fn performed_notes(&self) -> Vec<Note>
}
```

呼ぶのは `collect_events`（再生と WAV が共用）、`midi::to_bytes`、`ccs::export` の3箇所。

### 重なりの回避

開始と終端の**両方に同じ関数を通し**、`音価 = 新しい終端 − 新しい開始` とする。
オフセットは時刻だけの関数なので、前のノートの終端と次のノートの開始には必ず同じ値が
乗り、**重なりも隙間も生じない**。元コードの `end_delay` はこれで自然に再現される。

### 副作用 (3点)

いずれも表拍の遅れ（120BPM で 0.098拍 ≒ 32分音符弱）が原因。

**(a) 音価が負になりうる**

拍頭から始まる 32分音符より短いノートは、終端が開始より前に来る。

```
[0.0, 0.0625] (64分) → 開始 0.098、終端 0.0625 → 音価 −0.036
```

最小音価の下限 (1/64 拍) を設ける。この極端な場合だけ、次のノートとごくわずかに
重なる可能性が残るが、これは避けられない。

**(b) ノートの順序が入れ替わりうる**

変換は単調ではない。拍頭から 0.098拍以内に始まるノートは、拍頭のノートより前に出る。

```
0.00 → 0.098
0.05 → 0.05    ← 追い越される
```

再生では `collect_events` が時刻でソートし直すので破綻しない。CCS も `collect_parts`
がソートする。**論文のモデルに忠実な帰結**（表拍だけが遅れ、他は同期）なので、
意図的にそのままにする。装飾音を拍頭直後に置くと影響が出る、という位置づけ。

**(c) 最後のノートが終端をはみ出す**

`end_sample` は記譜位置から小節境界に切り上げて決まる。4/4 で最後のノートが 4.0 で
終わる場合、`end_sample` は 4.0 だが、演奏位置では 4.098 まで伸びる。

トランスポートの終端フラッシュは `event.sample_time > end_sample` で打ち切るため、
**このノートのノートオフが発行されず、音が鳴りっぱなしになる**。「最後のノートが
小節線ちょうどで終わる」のは最も普通の書き方なので、高確率で踏む。

対策は**演奏位置の終端を記譜の小節境界で頭打ちにする**。

| 案 | 結果 |
|---|---|
| 小節を1つ足す | 空の1小節が常に付く。見た目が悪い |
| `end_sample` を 0.098 拍伸ばす | ループ点がずれ、繰り返すたびに流れる |
| **終端を小節境界で頭打ち** (採用) | 最後のノートだけ最大 0.098 拍短くなる。ループは正確なまま |

## `.ron` プロジェクト形式

拡張子 `.ron`、依存は `ron` + `serde`（どちらも MIT OR Apache-2.0、純 Rust）。
RON は enum をそのまま書けるので、`ScaleMode` が文字列にならずに済む。

```ron
(
    version: 1,
    tempo: 120,
    beats: 4,
    beat_type: 4,
    scale: Equal12,
    swing_peak_ratio: 1.5,
    tracks: [
        (name: "トラック 1", lanes: 1, muted: false, soloed: false, swing: false),
    ],
    notes: [
        (start: 0.0, duration: 1.0, semitone: 0, octave: 4, velocity: 100, track: 0, lane: 0),
    ],
)
```

### 意図しない入力を弾く

serde は構文と型しか見ないので、意味の検証を別に持つ。方針は
**エディタに触る前に全部検証し、1つでも駄目なら何も変更しない**。

1. **`version` だけ先に読む。** 未知の（新しい）バージョンならそこで拒否する。
   全体を先に解析すると、将来の形式に対して意味不明な構文エラーが出るため
2. 全体を解析。失敗したら RON が返す**行・列つき**のエラーをそのまま見せる
3. 意味の検証（下表）。問題を**まとめて列挙**して通知に出す
4. すべて通ったらエディタへ反映

| 対象 | 条件 |
|---|---|
| `tempo` | 1..=999 |
| `beats` | 1 以上 |
| `beat_type` | 1 / 2 / 4 / 8 / 16 / 32 のいずれか |
| `swing_peak_ratio` | 1.0..=2.0 に丸める |
| `tracks` | 1本以上、`lanes` は 1 以上 |
| `notes` の `start` / `duration` | **有限**であること (NaN・Inf を弾く)、`start >= 0`、`duration > 0` |
| `notes` の `semitone` | その音階の 0..=`max_semitone` |
| `notes` の `track` / `lane` | 存在するトラック・段の範囲内 |

NaN の混入は特に危険。並べ替え・長さ計算・描画すべてに波及するので必ず弾く。

**未知のフィールドは無視する**（`deny_unknown_fields` は付けない）。欠けたフィールドは
`#[serde(default)]` で埋める。新旧どちらのビルドでも開けるようにするためで、
互換性の門は `version` 1本に絞る。

## UI

```
[? 操作ガイド] │ [ファイル ▾] [出力 ▾] │ 保存先: song.ron
                   ├ 開く…                ├ WAV ファイルとして出力
                   ├ 保存 (Ctrl+S)        └ CCS ファイルとして出力
                   ├ 名前を付けて保存…
                   ├ ─────────
                   ├ MIDI インポート
                   └ MIDI エクスポート
```

- **スウィングの強さ**: ツールバーの「段幅」の隣にスライダー。
  `C = 1.0` が無効と等価なので、値がそのまま強さの表示になる
- **トラックごとの ON/OFF**: 左のトラック欄に `M` `S` と並べて1文字トグル (`W`)
- `Ctrl+S` の保存先が MIDI から `.ron` に変わる

## フェーズ分け

| フェーズ | 内容 | 状態 |
|---|---|---|
| **1** | `swing.rs`（曲線・clamp・位置判定）、`TrackInfo.swing`、`MidiEditor::performed_notes()` | **完了** |
| **2** | 4つの出力すべてに適用。終端の頭打ち処理 | **完了** |
| **3** | UI（強さスライダー、トラックのトグル、ヘルプ、README） | **完了** |
| **4** | `.ron` の保存・読み込み・検証、ファイルメニュー整理、`Ctrl+S` の切り替え | **完了** |

### フェーズ4で分かったこと (RON の書き出し)

- **省略可能な項目を `Option` にすると `Some(...)` がそのまま書き出される。** 手で
  読み書きする形式には邪魔なので、`#[serde(default = "...")]` の既定値関数にする
- **既定の整形はノート1件が9行になる。** 数百件で読めなくなるので
  `PrettyConfig::depth_limit(2)` を使い、配列の要素は1行に収める

### フェーズ1で分かったこと

三連符は**刻みは均等のまま保たれるが、音価は均等にならない**。3音目の終端は次の
拍頭にあたるため、表拍の遅れぶん (120BPM で 0.098拍) 伸びる。次のノートとは
繋がったままなので破綻はしない。副作用 (b) と同じ系統の帰結。

**同じ「跳ねた8分」でも書き方で鳴り方が逆になる** (120BPM / C=1.5)。

| 書き方 | 1音目 | 2音目 | 次の拍頭 | 間隔 | 比 |
|---|---|---|---|---|---|
| 8分の等分 + swing | 49ms | 283ms | 549ms | 234 → 266ms | **0.88 (短→長)** |
| 三連符の真ん中抜き | 49ms | 333ms | 549ms | 284 → 216ms | **1.32 (長→短)** |

前者は裏拍も比のぶん動くが、後者の 2/3 は表拍でも裏拍でもないので動かない。
そのため、8分の等分に swing を掛けるとトラック単体では「短→長」になる。

論文の枠組みでは、伴奏の裏拍も同じ比の位置にあるはずなので、ソリスト単体で
測った比が 1 を割ること自体は想定内。ただし現状の `swing: bool` では伴奏が
その形を再現できない (伴奏を OFF にすると裏拍が 250ms に残り、ソリストの
283ms と 33ms ずれる)。

「比のみ (伴奏) / 比 + 遅れ (ソロ)」の3状態にする案を検討したが、**bool のまま
進める判断**とした。

### フェーズ3で分かったこと (egui の折り返しレイアウト)

ツールバーが 1100px に収まらなくなったので `horizontal_wrapped` に変えたが、
そこで2つ踏んだ。どちらも**画面外へ消えて操作できなくなる**類の不具合。

- **`add_enabled_ui` / `scope` で包むと折り返しに参加しない。** 入れ子の Ui は
  1項目として現在位置に置かれ、そのまま右へはみ出す。有効・無効はウィジェット
  個別の `add_enabled` で掛け、ラベルもスライダーも折り返しの直接の子にする
- **ラベルの文字が途中で改行される。** 「スウィング」が「ス」と「ウィング」に
  割れた。`wrap_mode(TextWrapMode::Extend)` で1語として次の行へ送る

### フェーズ2で分かったこと

**音価0以下のノートはスウィングの対象外にする必要がある**。最小音価の下限を
掛けてしまうと、各出力の「音価0は書き出さない」判定をすり抜け、スウィングの
有無で書き出される数が変わってしまう。

各フェーズ単体でコミットできる。フェーズ2 の終わりでスウィングは完全に動く。

## テスト計画

**曲線と clamp**

- 比: 120BPM で 1.308、200BPM で `C` ちょうど、`C = 1.0` なら全テンポ 1.0
- 比の clamp が 71BPM 未満・329BPM 超で効くこと
- 遅れ: 120BPM で 49ms、60BPM で 60ms 頭打ち、境界が 103BPM 付近であること

**変換の性質（重なり回避の核心）**

- **前のノートの終端と次のノートの開始が一致し続けること**（拍頭↔裏拍、裏拍↔次の拍頭）
- 音価が負にならないこと（64分音符を拍頭に置く）
- 三連符の2・3音目が動かないこと、連符スナップの誤差 (`0.9999998`) を拍頭と認識すること

**適用条件**

- 4/4・3/4 で適用、3/8・6/8・5/16 で無適用
- `enabled` が偽のトラックが1 tick も動かないこと
- 伴奏とソロを同時に鳴らして片方だけずれること

**終端**

- 小節線ちょうどで終わるノートが `end_sample` を超えないこと
  （**鳴りっぱなし防止。回帰しやすいので明示的に固定**）

**`.ron`**

- 往復でモデルが一致すること
- 未知のフィールドを無視し、欠けたフィールドが既定値で埋まること
- 弾くべき入力を弾くこと: 構文エラー / 新しい `version` / `tempo: 0` / `beat_type: 3` /
  `duration: 0` / **`start: NaN`** / 範囲外の `track`
- 検証に失敗したとき、**エディタの状態が一切変わらないこと**

## 既知の割り切り

- 拍子は N/4 のみ。2/2 (カットタイム) は 4/4 と同じ音楽の別記法なので、
  将来対象へ入れたくなる可能性がある。判定は1箇所の関数に閉じ込めておく
- スウィングの強さは全体設定、ON/OFF はトラックごと。
  強さをトラックごとに移すのは `#[serde(default)]` のおかげで1フィールド追加で済む
- 音源 (.clap) のパスは `.ron` に含めない。`clap.state` 未対応でパラメータが
  初期値に戻るため、「開いたのに音が違う」という中途半端な体験になる
- MIDI エクスポートにもスウィングを適用するため、書き出した MIDI を読み戻すと
  スウィング済みの位置が記譜として入る（二重適用）。保存は `.ron` で行うので許容する
