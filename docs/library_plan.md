# プラグイン一覧の計画

フォルダを登録して中の `.clap` / `.vst3` を走査し、**一覧から音源を選べる**ようにする。
今はファイルダイアログで毎回パスを辿っているが、DAW と同じく登録済みの一覧から
選ぶ形にする。

## やりたいこと (出発点)

- 別ウィンドウで管理する
- フォルダを自分で足していき (`.../Common Files/CLAP` 等)、その中を走査する
- 1つのファイルに複数のプラグインが入る場合は**それぞれの名前で記録する**
- **音源とエフェクトを見分けてタブを分ける**
- オーディオトラックの音源読み込みを、この一覧から行う形に変える
- お気に入りを星で記録し、別タブで参照しやすくする
- 記録は `.ron` で残す

## 調べて分かったこと

### 種別は**インスタンス化せずに**取れる

音源とエフェクトの見分けに、プラグインを起動する必要は無い。どちらの形式も
ファクトリを読むだけで分かる。

| 形式 | どこを見るか | 値 |
|---|---|---|
| CLAP | `PluginDescriptor::features()` | `instrument` / `audio-effect` |
| VST3 | `ModuleClassInfo::sub_categories` | `Instrument` / `Fx` |

**これが決め手。** 起動してから入力ポートの有無で判断する形だと、走査のたびに
全プラグインを activate することになり、時間もリスクも跳ね上がる。

ついでに `vendor` と `version` も同じ経路で取れるので、一覧に出せる。

### 今ある走査の口がほぼそのまま使える

`discovery::load_clap_file` / `load_vst3_file` は既に「1ファイル → プラグインの一覧」
を返す形で、失敗も `Result` で返る。**足りないのは種別とベンダーだけ**なので、
`FoundPlugin` に項目を足せば済む。

### 読み込む側は変えなくてよい

`App::load_plugin(track, kind, path, id, state)` は既に **(形式, パス, ID)** で
音源を載せられる。一覧が持つのもまさにこの3つなので、**載せる経路は無改造**で、
選ばせる画面だけを差し替えればよい。

### 検証用プラグインがそのまま治具になる

`target/test_plugin.clap` は**1ファイルに2つ**入っていて、しかも
`INSTRUMENT` と `AUDIO_EFFECT` が1つずつある。

| ID | features | 期待する分類 |
|---|---|---|
| `com.example.test-sine` | `SYNTHESIZER` `MONO` `INSTRUMENT` | 音源 |
| `com.example.test-gain` | `AUDIO_EFFECT` `MONO` `UTILITY` | エフェクト |

「複数入り」「音源とエフェクトの両方」を1ファイルで確かめられる。
VST3 版 (`target/test_plugin.vst3`) も同じ2つを持つので、形式をまたいだ確認もできる。

## 記録の置き場: **実行ファイルの隣の `config/`** (決定)

```
<実行ファイルのあるディレクトリ>\config\plugins.ron
```

`cargo run` で動かすと `target\debug\config\plugins.ron` になる。

`%APPDATA%` を薦めたが、**「管理が煩雑になる」「消えるのは実験環境だけなので
構わない」**という判断で、実行ファイルの隣に決めた。設定が実行ファイルと
一緒に動くので、持ち運びも素直になる。

- 場所は `std::env::current_exe()` の親 + `config`
- ディレクトリが無ければ作る
- `current_exe()` が取れない環境では作業ディレクトリの `config` へ落とす

**`cargo clean` すると消える。** 走査し直しには時間がかかるので、
消えて困るときは `config` を退避すること (guide.md に書く)。

## 記録の形

```ron
(
    version: 1,
    // 走査するフォルダ (初回は標準の置き場のうち実在するものを入れる)
    folders: [
        "C:\\Program Files\\Common Files\\CLAP",
        "C:\\Program Files\\Common Files\\VST3",
    ],
    plugins: [
        (
            kind: Clap,
            path: "C:\\Program Files\\Common Files\\CLAP\\Foo.clap",
            id: "com.example.foo",
            name: "Foo Synth",
            vendor: "Example Audio",
            version: "1.2.0",
            role: Instrument,   // Instrument / Effect / Unknown
            favorite: false,
        ),
    ],
    // 走査中に落ちたファイル。次からは飛ばす (画面から消せる)
    blocked: [],
)
```

- `kind` は `project::PluginKind` を**使い回す** (既に serde 対応で、
  プロジェクトファイルと同じ綴りになる)
- `path` + `id` の組が1つのプラグインを指す。**載せるのに要るのはこの3つだけ**
- `#[serde(default)]` を付けて、項目を足しても古いファイルが読めるようにする
  (プロジェクトファイルと同じ方針)

## 走査の作り

### メインスレッドで、1ファイルずつ進める

**別スレッドにしない。** CLAP も VST3 もモジュールの読み込みはメインスレッドの
規約に縛られており、裏で読んで持ち回るのは危うい。

代わりに**毎フレーム1ファイル**だけ処理する。窓は進捗を出しながら反応を保てるし、
途中でやめられる。スレッドも共有状態も要らない。

```
待ち行列: [Foo.clap, Bar.vst3, ...]
毎フレーム: 1つ取り出す → 中を数える → 一覧へ足す → 進捗を描く
```

### フォルダの辿り方

- 再帰する。ベンダーが `Common Files\VST3\<Vendor>\Foo.vst3` と掘ることがある
- **`.vst3` のディレクトリには入らない。** バンドルそのものが1つのプラグインなので、
  中の `Contents\x86_64-win\Foo.vst3` を別に数えてはいけない
- `.clap` は Windows では素のファイル

### 落ちたときにどうするか — **同一プロセス + 復帰情報** (決定)

**走査は任意の DLL を実行することと同じ。** 相手が悪ければ落ちるし、
ライセンス確認のダイアログを出して固まることもある。実際このプロジェクトでも
`editor_smoke` は「エディタの生成はクラッシュしうる」ので**音源1つにつき1プロセス**
にしてある。

同じプロセスで走査し、**開く直前にそのパスを目印のファイルへ書く**。

```
config\scanning.txt   ← 今開いているファイルのパス。開き終えたら消す
```

- 起動時にこれが残っていれば、**前回そこで落ちた**ということ
- そのパスを `blocked` へ移し、目印を消す。次からは飛ばす
- 画面に「このファイルで落ちました」と出し、`blocked` から外せるようにする

記録を全部書き直すのではなく**小さな別ファイル**にするのは、1ファイルごとに
`.ron` 全体を書き直すと走査が遅くなるため。

> 子プロセスで走査する形 (DAW と同じ) は、必要になったら足せる。
> 自分の実行ファイルを `--scan-one <path>` で呼び直すだけで、検証バイナリと
> 同じ作りになる。**どのプラグインで落ちたかは上の記録で必ず分かる**ので、
> それが要るかどうかも実際に落ちてから判断できる。

## 分類とタブ

| タブ | 中身 |
|---|---|
| 音源 | `Instrument` |
| エフェクト | `Effect` |
| 未分類 | `Unknown` (種別を宣言していないもの) |
| お気に入り | 星を付けたもの (種別を問わない) |

**未分類は独立したタブにする。** 音源とエフェクトの両方へ出すと数が二重になり、
「宣言が無い」という事実も見えなくなる。別のタブなら、そこに何が居るかが
そのまま分かる。

## 読み込み経路の差し替え

今: 「+」→ 形式を選ぶ → ファイルダイアログ → (複数なら) プラグインを選ぶ

後: 「+」→ **一覧の窓**が開く (段に合わせて音源/エフェクトのタブを最初に出す)
→ 選ぶと載る

**ファイルから直接読む道は残す。** 一覧に無いものを試したいときや、走査で
落ちるプラグインを個別に確かめたいときに要る。一覧の窓に
「ファイルから直接…」を置いて、今の流れへ繋ぐ。

## フェーズ

### フェーズ1: 記録の形と読み書き — 済

`host/src/library.rs` にデータと `.ron` の入出力だけを作った。画面も走査も無し。

| 出したもの | 中身 |
|---|---|
| `Role` | `Instrument` / `Effect` / `Unknown` |
| `Entry` | 1件 (`kind` `path` `id` `name` `vendor` `version` `role` `favorite`) |
| `Library` | `folders` / `plugins` / `blocked` と、絞り込み・星・並べ替え |
| `to_string` / `from_str` | `.ron` の入出力 (版の門つき) |
| `config_dir` / `config_path` | 実行ファイルの隣の `config\plugins.ron` |
| `mark_scanning` / `clear_scanning` / `take_crashed` | 落ちたときの目印 |
| `standard_folders` / `existing_standard_folders` | 規格の置き場 (Windows / Linux) |

テスト14件。**`cargo test --lib` だけで完結する** (走査もファイルも要らない)。

決めたこと:

- **`path` + `id` の組で1つのプラグインを指す。** 同じプラグインを2箇所に
  置いている環境があるので、ID だけでは足りない
- **走査し直しても星は残す。** 名前と種別は新しいもので上書きし、`favorite`
  だけ引き継ぐ (`Library::insert`)
- **パスか ID が空の記録は読み飛ばす。** 指し示す先が無いものを一覧に出しても
  読み込めないだけ

### フェーズ2: 走査

- `FoundPlugin` に `role` / `vendor` / `version` を足す
- フォルダ → 候補の一覧 (再帰・`.vst3` バンドルの扱い)
- 1ファイルずつ進める形
- `scan_smoke` — フォルダを渡すと中身を出す検証バイナリ。
  `target` を渡せば `test_plugin.clap` と `.vst3` から
  **音源1つ・エフェクト1つ**が出るはず

### フェーズ3: 窓

フォルダの追加・削除・再走査、進捗、タブ、お気に入りの星。

### フェーズ4: 読み込み経路の差し替え

オーディオトラックの「+」を一覧の窓へ。直接読む道は残す。

## 既定のフォルダ — **標準の置き場を入れる** (決定)

初回起動時に、規格が決めている置き場のうち**実在するものだけ**を入れる。

**Linux のぶんも今のうちに書いておく。** 動かすのは Windows だけだが、
場所の一覧はただのデータなので、あとから足すより最初から並べたほうが安い。

| | CLAP | VST3 |
|---|---|---|
| Windows | `%COMMONPROGRAMFILES%\CLAP`<br>`%LOCALAPPDATA%\Programs\Common\CLAP` | `%COMMONPROGRAMFILES%\VST3`<br>`%LOCALAPPDATA%\Programs\Common\VST3` |
| Linux | `/usr/lib/clap`<br>`/usr/local/lib/clap`<br>`~/.clap` | `/usr/lib/vst3`<br>`/usr/local/lib/vst3`<br>`~/.vst3` |

macOS (`/Library/Audio/Plug-Ins/...`) は同じ形で足せるが、動かす当てが無いので
今は入れない。

## 決めたことのまとめ

| | |
|---|---|
| 記録の置き場 | 実行ファイルの隣の `config\plugins.ron` |
| 落ちたときの扱い | 同一プロセス + `config\scanning.txt` の目印 |
| 既定のフォルダ | 標準の置き場のうち実在するものを入れる (Linux 用も用意) |
| 分類できないもの | 「未分類」タブへ (音源・エフェクトの両方には出さない) |
